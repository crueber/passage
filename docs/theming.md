# Theming

Passage ships thirteen colour themes. The server default is chosen in Settings →
General (`ui.theme`), and each person can override it on their Profile page:

```html
<html lang="en" data-theme="slate">
```

A theme is nothing but a set of CSS custom-property overrides scoped to that
attribute. The signed-in page data carries the account override; public pages
fall back to the server default.

## How the cascade works

Two stylesheets load on every page, in this order:

```html
<link rel="stylesheet" href="/static/passage.css">
<link rel="stylesheet" href="/static/themes.css">
```

| File | Generated by | Contains |
|---|---|---|
| `internal/web/static/passage.css` | `tools/build-css.sh` (Tailwind v4 CLI) | Tailwind utilities and the `@layer components` classes, plus a built-in fallback palette |
| `internal/web/static/themes.css` | `tools/build-themes.sh` (plain `cat`) | One `:root[data-theme="…"]` block per theme, light + dark |

`passage.css` puts its tokens inside `@layer` (via Tailwind). `themes.css` is
deliberately **unlayered**, and unlayered declarations beat layered ones
regardless of source order. On top of that, `:root[data-theme="x"]` has higher
specificity than the plain `:root` fallback in `passage.css`. So the selected
theme always wins, and the fallback in `passage.css` only matters if the theme
stylesheet fails to load.

Because the theme block is applied to `<html>` by the server, theming works
with JavaScript disabled, before scripts run, and without a flash of unstyled
content.

## The token contract

Every theme file must define exactly the same token set, in **both** the light
block and the dark `@media (prefers-color-scheme: dark)` block. A **light-only**
theme (Paper, GitHub Light, One Light, Ayu Light) repeats its light values in
the dark block so the palette never inverts; keep the explanatory comment at the
top of that block.

```
brand ramp        --color-brand-50 … --color-brand-950          (11)
surfaces + text   --color-canvas --color-surface --color-raised
                  --color-line --color-ink --color-muted --color-faint   (7)
primary actions   --color-primary --color-primary-hover --color-on-primary
                  --color-primary-soft --color-primary-soft-hover
                  --color-on-primary-soft                       (6)
status            --color-success --color-success-soft --color-on-success-soft
                  --color-danger --color-danger-hover --color-danger-soft
                  --color-on-danger-soft
                  --color-warn --color-warn-soft --color-on-warn-soft    (10)
accent            --color-glow                                  (1)
elevation         --shadow-card --shadow-pop                    (2)
```

The brand ramp has two load-bearing ends and must descend monotonically
(`50` lightest → `950` darkest) in **both** blocks: `--color-brand-50/60` is the
table row-hover wash, and `--color-brand-950/40` is the mobile admin drawer
scrim — if `950` is not darker than `--color-canvas`, opening the drawer
brightens the page instead of dimming it. `TestThemeFiles_BrandRamp` enforces
this; do not "invert" the ramp for dark mode.


File shape:

```css
/* mytheme — One-line description. */
:root[data-theme="mytheme"] {
  --color-brand-50: #f4f6f9;
  /* … */
  --shadow-card: 0 1px 2px 0 rgb(23 28 36 / 0.05), 0 4px 14px -4px rgb(23 28 36 / 0.1);
  --shadow-pop: 0 4px 10px -2px rgb(23 28 36 / 0.12), 0 16px 40px -12px rgb(23 28 36 / 0.25);
}
@media (prefers-color-scheme: dark) {
  :root[data-theme="mytheme"] {
    /* same token set, dark values */
  }
}
```

Rules:

- Colour tokens are **6-digit hex literals** (`#rrggbb`). Tests parse them to
  compute WCAG contrast, so `rgb()`, `hsl()`, named colours, and shorthand hex
  are rejected.
- Shadows are the one exception: they are `rgb(…)` with a slash-alpha channel,
  tinted with the theme's ink colour (light themes) or black (dark themes).
- Never wrap theme rules in `@layer`.
- Never reference another theme's values or use `var()` fallbacks across themes.

## Adding a theme

1. Create `internal/web/ui/themes/<name>.css` using the slug as the filename
   and as the `data-theme` value.
2. Run `./tools/build-themes.sh` (or `make themes`) to regenerate
   `internal/web/static/themes.css`.
3. Register it in `internal/theme/theme.go` (`All`, in display order) with a
   `Label` and a one-line `Description`.
4. Run `go test ./internal/theme/ ./internal/web/` — the guardrail tests check
   the file/registry match, the token contract, and WCAG contrast.
5. Mention the theme in `passage.example.yaml` and `.env.example` if the
   valid-name list is enumerated there.

`themes.css` is generated — never hand-edit it, and commit it in the same change
as the source file. CI runs `./tools/build-themes.sh --check` and fails if the
committed bundle is stale.

## Contrast gate (WCAG AA)

For every theme, in both light and dark:

| Pair | Minimum |
|---|---|
| `ink` on `canvas` | 4.5:1 |
| `ink` on `surface` | 4.5:1 |
| `muted` on `surface` | 4.5:1 |
| `faint` on `surface` | 3.0:1 |
| `primary` on `surface` | 4.5:1 |
| `on-primary` on `primary` | 4.5:1 |
| `on-primary-soft` on `primary-soft` | 4.5:1 |
| `on-success-soft` on `success-soft` | 4.5:1 |
| `on-danger-soft` on `danger-soft` | 4.5:1 |
| `on-warn-soft` on `warn-soft` | 4.5:1 |

A failure names the pair, both hex values, and the measured ratio, so tuning is
a value swap rather than guesswork. This test is the gate for new themes.

## Server default and per-account override

Admin → Settings → General sets the server default (`ui.theme`, stored in the
settings table). There is no per-browser picker.

- Each user may choose a theme on their **Profile** page. The slug is stored in
  `users.theme`; an empty value follows the server default.
- Theme resolution is server-side. Every full-page template renders
  `<html … data-theme="{{theme .}}">`. Signed-in page data embeds
  `web.Themed` (populated from the loaded user); public pages do not, so the
  `theme` function returns the server default.
- No `localStorage` and no client script are involved: the rendered attribute is
  authoritative, so pages are themed with JavaScript disabled.
- `user.Service.UpdateTheme` rejects an unregistered slug (`ErrInvalidTheme`)
  and the profile handler refuses it before writing, so a stray form value
  cannot produce an unthemed page.

## Files at a glance

```
internal/web/ui/themes/*.css     source of truth, one file per theme
internal/web/static/themes.css   generated bundle (commit it)
internal/web/templates.go        web.Themed + ThemeFromData (server-side resolution)
internal/theme/theme.go          registry (names, labels, descriptions)
internal/theme/theme_test.go     slug/registry/token/contrast guards
tools/build-themes.sh            build + --check
```

`passage.css` remains a Tailwind artifact and is rebuilt with
`tools/build-css.sh`; `themes.css` is not touched by Tailwind at all. Do not add
`@import` lines for themes to `input.css` — Tailwind cannot compile them and
they must stay unlayered.
